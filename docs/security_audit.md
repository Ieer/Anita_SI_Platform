# 安全说明与审计状态

更新日期：2026-10-17。本文是代码与部署风险说明，不是渗透测试报告、安全认证或生产上线批准。本次依赖扫描覆盖锁定的 Windows/Python 3.11 运行依赖；漏洞数据库和后续依赖变更仍需持续复查。

## 当前实现中的防护

- 调度 RPC 使用 HMAC 挑战认证，Web 与 scheduler 需设置相同的 `SMART_AGENT_SCHEDULER_RPC_SECRET`；RPC 禁用 pickle 和公开属性访问。HMAC 不加密网络流量，服务仍应限制在受控网络/loopback，不要暴露公网。
- Web 与 APScheduler 由独立进程管理；统一启动器检查服务状态和进程身份，不会接管未知进程。APScheduler 3.x 持久 Job Store 不应由多个 scheduler 实例共享。
- 任务操作在服务端重新核对页面权限、团队归属和具体动作。脚本由服务端重新读取；浏览器不能通过伪造行数据提交脚本。
- 同一平台任务使用持久请求键和运行护栏。回执不确定时保留 `unknown`，不自动重试或释放护栏；Windows 原生任务与 APScheduler 保持独立。
- Agent 默认不启用模型或任务执行。日志发送需用户同意并进行尽力脱敏；已有任务执行需显式白名单、版本核对和人工批准，未知提交不自动重试。
- SQL 参数通过 ORM 处理；头像路径、OAuth2 回调和登录回跳在服务端校验。以上控制不能替代对新页面回调和新 API 的逐项授权审查。

## 发布与本地配置

实际配置路径为 `src/config/anita_go.ini`，包含数据加密、Cookie 和 JWT 密钥。旧 `src/config/dashgo.ini` 会在新文件不存在时兼容读取。两种实际配置文件均加入 Git 忽略；仓库只应发布 `src/config/anita_go.ini.example` 占位模板。部署人员须各自生成独立密钥，不得把真实配置、数据库、备份、用户头像或运行缓存加入版本库。

新库初始化不再提供默认口令。交互终端隐藏输入并确认唯一的管理员密码（16 到 1024 个字符）；无人值守部署须由密钥系统注入 `SMART_AGENT_INITIAL_ADMIN_PASSWORD`，缺少或不合格口令时初始化失败。口令不写入命令行、模板或日志，初始化后清除该环境变量。重复初始化不改变已有管理员密码、停用状态或角色。历史默认口令必须主动更改，自动升级密码散列不会使公开口令本身变安全。RPC 共享密钥不等同于加密密钥，也不应写入 INI 示例、源代码或提交记录。

## 密码存储与迁移

- 新建、重置、编辑和个人改密统一使用 scrypt；输入为现有协议的 SHA-256 摘要，随机盐 16 字节，`N=32768, r=8, p=3`，派生密钥 24 字节。`s1$` 版本前缀加 Base64url 编码共 57 字符，兼容现有 64 字符字段，SQLite/MySQL 无需因此修改表结构。工作因子属于版本契约，未来调整需使用新版本前缀。
- 旧 64 位十六进制摘要仅兼容验证，成功后以条件更新迁移，避免覆盖并发改密；错误密码和停用账号不会迁移。密码登录、Basic 密码验证、改密旧密码确认和 OTP 配置密码确认均复用同一验证入口。
- 部署代码后须重启相关服务，禁止新旧密码验证代码混合运行；旧版本无法识别新格式，不能在没有兼容计划时回滚到旧代码。
- 尚未验证密码的旧账号仍保留旧摘要。应安排长期不登录或仅用 OTP 的账号重置密码，数据库备份仍需访问控制。历史摘要若已泄漏，必须重置口令，不能仅依赖重新散列。
- 浏览器发送的 SHA-256 摘要仍是可复用凭据，不是挑战响应协议。scrypt 改善数据库泄漏防护，但不能阻止被窃登录摘要重放；远程访问必须使用 HTTPS，并保护日志、浏览器和代理链路。

## 尚未解决的风险

| 风险 | 影响与要求 |
| --- | --- |
| 历史默认口令与未迁移摘要 | 新库已要求唯一口令且新密码采用 scrypt；已有公开口令仍须更改，旧账号需成功密码验证或重置才能完成散列升级。 |
| 登录摘要仍可作为凭据重放 | 保留了现有客户端 SHA-256 协议，必须使用 HTTPS；若摘要已泄漏，需重置密码。 |
| 本地密钥轮换未完成 | 更换 `ENCRYPT_KEY` 可能使数据库中已有加密凭据无法解密。轮换前须备份并设计逐项解密/重加密流程，不能直接覆盖密钥。 |
| RPC 仅认证、不加密 | loopback 外部通信需部署在受信网络或增加受支持的安全传输层；不要直接绑定或转发到公网。 |
| 任务脚本与 SSH 不构成沙箱 | 本机脚本继承 scheduler 服务账户权限；SSH 脚本在远端账户权限下执行。使用低权限账户、限制可编辑/运行人员和出站访问。 |
| 日志脱敏不能保证移除全部秘密 | 导出、工单和 Agent 外发前仍需人工确认。运行日志可能包含业务敏感数据。 |
| MySQL 与第三方联调未获生产认证 | SQLite 维护演练不能替代 MySQL 并发/迁移验收；真实 SSH、SMTP/通知供应商、第三方 OAuth2 客户端和真实模型尚需隔离环境联调。 |
| 依赖漏洞门禁尚未通过 | 本次完整运行锁审计发现 6 个包存在已知漏洞；历史缓存不能代替当次报告。修复需兼容性回归，不能忽略漏洞使门禁通过。 |
| 部署边界需由运维配置 | 需配置 TLS、可信反向代理、监听范围、请求限制、跨进程限流、日志保留和密钥存储；开发服务器不适用于公网生产。 |

## 验证范围

交付工作流包含独立的依赖审计 job，扫描带哈希的完整运行依赖锁文件，不只扫描直接依赖。发现漏洞或查询失败均阻断该 job；功能测试通过不代表安全门禁通过。当前直接依赖基线已发现已知漏洞，未因加入 CI 而自动修复，也未自动接受跨主版本升级。最新明细以当次生成的 `cache/report/ci/dependencies.json` 和 GitHub artifact 为准，历史缓存不能证明当前安全。

2026-10-17 本地实测：完整运行锁包含 85 个包，审计返回退出码 1，记录 6 个受影响包、66 条漏洞记录（不等同于去重后的 CVE 数量）：`markdown`、`orjson`、`paramiko`、`pillow`、`pyjwt`、`requests`。本次未执行漏洞忽略或自动修复，安全 job 仍应阻断。

本地隔离门禁与锁文件更新命令见 [README 的交付检查](../README.md#可复现交付检查)。GitHub 分支保护需由仓库管理员将回归及依赖审计都配置为必需检查；仅提交 workflow 不会自动启用分支保护。

可在隔离环境执行：

```powershell
python -m pytest tests -q
```

默认测试不代表真实模型、SSH、第三方 OAuth2、生产 MySQL 或真实业务任务已联调。Windows 原生任务生命周期探测须阅读测试说明并显式启用；这类探测会修改本机计划任务，不要在生产主机运行。

隔离任务中心浏览器测试需显式设置 `PLATFORM_TASK_UI_PROBE=1`，并指向由 `scripts/demo_task_center.py` 启动的临时演示服务。Agent 浏览器测试使用临时 SQLite 和模拟模型传输，不调用真实模型；具体命令见[任务中心指南](task_center.md#隔离演示与浏览器验收)。

## 上线前检查

- 生成唯一的加密、Cookie、JWT 和 RPC 密钥；新库使用唯一管理员口令，历史默认口令已更改，旧账号迁移或重置计划已落实。

- TLS、反向代理信任链、Cookie、安全响应头、请求体限制和限流已由部署环境验证。
- 任务及 SSH 目标经过人工审查；未知运行已核实，任务恢复策略已获批准。
- 当前依赖和容器（如有）完成扫描、漏洞修复评审与回归测试。
